## [Unreleased]

### Added

- `/write-plan-fast` saves a short plan under `.repo/plans-fast/` when the person asks for one, and `/implement-plan-fast {n}` runs it inline in a `fast-{serial}-{name}` worktree with no subagents and no journal. A fast plan holds Goal, Steps and Verify as flat `N [ ] text` boxes in at most 40 lines, has no strategy and no review, and is denied with `a fast plan is at most 40 lines; write a plan (/write-plan)` when over. Its approval block is `fast-plan {n}` with `i` implement and `h` hand off only. Format: `references/fast-plan-format.md`.
- Under the standards pack `repo sync` adds editor defaults to `.vscode/settings.json` and `.vscode/extensions.json`, only where a key or recommendation is missing, so a value you set is never changed: format on save through Bun (`bun fmt --no-script --stdin-filepath` run by the Simple LSP Client extension, since Bun has no language server), the oxc extension for lint only (`oxc.enable.oxfmt: false`, fix-all on save), final newline, LF, trimmed whitespace and search and watcher excludes. By what is installed it also adds the workspace TypeScript (`js/ts.tsdk.path` and `js/ts.experimental.useTsgo` for TypeScript 7 or later, `typescript.tsdk` for older), `.css` as `tailwindcss` with no false at-rule errors when there is a Tailwind entry sheet, and the Tailwind, TypeScript 7 and Vitest extension recommendations. Run `bun repo sync` and commit the two files.
- `.repo/backlog.md` is a gitignored checklist of things found but not done now, with `- [ ]` open, `- [-]` in progress and `- [x]` done lines. The `backlog` skill adds, lists, starts, finishes and clears items (`/backlog fix flaky doctor test`, `/backlog start 2`, `/backlog done 2`, `/backlog clear`), reads a hand-edited file as is and rewrites only the box of the line it acts on, and one always-on rule tells agents to log anything outside the active plan or roadmap there instead of fixing it. `repo sync` ignores `**/.repo/backlog.md`, and `repo clean` keeps it.
- The shell gate denies an agent's local whole-ci run (`bun repo ci`, `repo ci --no-coverage`, `bun run ci`, in a compound too) with `GitHub runs ci, not you: push the branch, then run bun repo ci wait <branch>`, and rewrites `bun test` to `bun run test` for every caller, so bun's own runner never meets the vitest suites. `repo ci wait`, `skips`, `times` and `merge` pass.
- `repo eval <name>` runs `evals/<name>/eval.ts` against the Anthropic API and prints `pass <id>` or `fail <id>` per case (controls marked), then `spent $0.0121 of $1.00`. It first prints a worst-case estimate (`eval skill-routing: 12 cases x 3 samples = 36 calls on claude-haiku-5-5, at most $0.0187 (cap $1.00)`) and refuses over the cap (default $1.00; `--max-cost <usd>` raises it) before any call. `--dry-run` stops after the estimate and needs no key; a real run needs `ANTHROPIC_API_KEY`. The default model is `claude-haiku-5-5`, with 3 samples and 256 max tokens; an eval file sets its own with `defineEval` from `cli/eval/spec.ts`. `evals/` is not packaged.
- `repo github` turns on and checks secret scanning, push protection and Dependabot security updates (`repo github: secret scanning is off: run bun repo github`). The release pack also writes `.github/dependabot.yml` for GitHub Actions (weekly, 7-day cooldown), and the generated `ci.yml` skips `test` and `e2e` on draft pull requests and runs again on `ready_for_review`. `repo check` holds the size of the shipped agent context in `context-budget.json` against main's: a rise needs `bun repo check --write --reason "<why>"`, which appends a line to `.repo/context-growth.jsonl`.
- `bun repo yolo` covers opencode (V2): it merges one allow-all rule into `~/.config/opencode/opencode.json` ahead of the rules already there, so a user's own `deny` or `ask` still wins. A dest whose `permissions` is not a list, or one with an `opencode.jsonc` beside it, is left as is (`skip opencode .config/opencode/opencode.json: <reason>`; `--check` prints `opencode skipped: <reason>` and exits 1).
- `bun repo shim` installs a `repo` command (`~/.local/bin`, or `%LOCALAPPDATA%\workerstack\bin` on Windows) that runs the nearest project's own `@workerstack/repo` from any directory, so `repo doctor` works without `bun run`; `--dry-run`, `--check`, `--dir <path>`; it reads PATH with the host's delimiter, so a Windows drive letter does not split an entry. `bun repo doctor` shows a `shim` row.
- `repo sync` reads `engines.node` from the root and every workspace package's `package.json`: when they declare one range (`"engines": { "node": ">=22" }`), the generated `ci.yml` sets up that node right after setup-bun in the test, e2e and coverage jobs (`- uses: actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1 # v7.1.0` with `node-version: ">=22"`), in place of the steps that remove node, so an app that ships on node is tested on it; a repo that declares no range gets the same `ci.yml` as before.
