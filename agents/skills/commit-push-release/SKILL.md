Run `/commit-push`, then:

## Release

Run `bun repo release` from the main checkout (not a worktree), on the default branch, clean and equal to origin, after `/commit-push` landed the commits. It waits on its own release-commit push itself. Do not ask the user for a bump and do not edit `package.json`: the command reads the Conventional Commits since the last tag. Add `--stable` (0.x to 1.0.0) or `--pre <id>` only when the user named them. Every feat fix perf or breaking commit in a public package adds its entry with `bun repo changelog add <section> "<text>"` which writes it under `## [Unreleased]` and stages it; the hook refuses the commit otherwise and the release refuses an empty Unreleased.

1. `bun repo release` commits `chore: release <name>@<version>` (the version line and CHANGELOG.md only), pushes it, waits on CI for that commit, then tags `<name>@<version>` and pushes the tag. Its last line names the tag. A refusal prints one line that starts with repo release: and has written nothing; fix what it names and run it again.
2. When CI failed, read the jobs it printed, fix the cause with a failing test first and a CHANGELOG.md entry, push, and run `bun repo release` again. A rerun finishes the same version and never bumps twice. A cancelled or missing CI result is the same: pull if told to, run it again.
3. The tag push starts `release.yml` (generated by `bun repo sync`), which runs three jobs. **gate** checks that the tag equals the version in package.json at the tagged commit, that CHANGELOG.md has that version's section, that the commit is on the default branch and that its CI passed. **publish** packs, refuses a `catalog:` or `workspace:` version in the packed manifest, skips a version npm already serves and publishes through trusted publishing (no npm token), under `next` for a prerelease. **github** creates the GitHub release from the changelog section. Each job reruns safely: `gh workflow run release.yml -f tag=<name>@<version>` finishes a release that stopped halfway.
4. After the tag, run `bun repo release wait <name>@<version>` from the main checkout. A pushed tag is not a release until it prints `published <version>`. It exits 1 after 15 minutes; report that and `gh run list --workflow release`. Do not watch runs by hand.
5. A package that is not on npm yet cannot publish from CI: the publish job fails and prints the bootstrap steps. Tell the user to run `npm login` and `bun repo release publish <name>@<version>` at that tag on their machine, then add the trusted publisher the line names. Never do it yourself.

Do not `bun publish` or `npm publish`. Do not `bun pm pack` as publish. Do not `gh release create`. CI publishes from the tag; the one exception is the first publish of a new package, which the user runs.

Never tag by hand, never `git tag -f`, delete a tag or force-push one. A tag never moves; a bad release is fixed by the next version.

Protocol: `node_modules/@workerstack/repo/references/cascade.md`. Do not paste cascade.
